1. STATE — MAINTENANCE SCHEDULE WORKFLOW
------------------------------------------------------------

Candidate:
State

LLM status:
NEWLY INTRODUCED

Human status:
CONFIRMED

Files inspected:
- Service/Maintenance/IMaintenanceState.cs
- Service/Maintenance/MaintenanceStateBase.cs
- Service/Maintenance/ScheduledState.cs
- Service/Maintenance/InProgressState.cs
- Service/Maintenance/CompletedState.cs
- Service/Maintenance/CancelledState.cs
- Service/Maintenance/MaintenanceContext.cs
- Service/MaintenanceService.cs
- Models/MaintenanceSchedule.cs
- FlemanApi.Tests/Services/MaintenanceStateTests.cs

Exact source evidence:
IMaintenanceState (IMaintenanceState.cs:8-15) declares Status, Start,
Complete and Cancel.

MaintenanceStateBase (MaintenanceStateBase.cs:10) makes Start, Complete and
Cancel virtual, and each throws ApiException 409 by default (lines 14-16).

The four concrete states override only the operations that are legal for
them:
- ScheduledState overrides Start, which checks that the car is AVAILABLE,
  sets it to UNDER_MAINTENANCE and moves to InProgressState
  (ScheduledState.cs:18-26), and Cancel, which moves to CancelledState
  (ScheduledState.cs:31).
- InProgressState overrides Complete and Cancel, and both release the car
  (InProgressState.cs:12-28).
- CompletedState and CancelledState override nothing; they are terminal.

MaintenanceContext selects the state object from the persisted Status with a
lookup table (MaintenanceContext.cs:28), delegates Start, Complete and
Cancel to it, and changes state through TransitionTo
(MaintenanceContext.cs:42).

MaintenanceService.TransitionAsync (MaintenanceService.cs:101-125) only
creates the context and calls the operation (line 118). It contains no
switch or if-chain on Status.

Test evidence: MaintenanceStateTests has 18 tests, covering every state x
operation combination and the context's state selection; all pass in
test_result.txt.

Reason:
Behaviour that varies by status is implemented by separate polymorphic
state objects. A context holds the current state and delegates to it, and
the states themselves perform the transitions. This is the full State
collaboration. In Part 1, State was REJECTED at the baseline because only
status enums existed; CH01 introduces real state objects, so it is newly
introduced, not reclassified.
