8. JAVA FIRST-RUN FAILURE AND FIX
------------------------------------------------------------

Claim:
Java failed D04b on its first run. addSingleton("X", Foo.class) with no
dependency arguments matched an addSingleton(String, Object) overload,
because Java prefers non-varargs overloads, so the Class object was
registered as the singleton. The overload was renamed addSingletonInstance.

LLM status:
CONFIRMED

Human status:
CONFIRMED

Files inspected:
- Java/DependencyInjection.java (addSingletonInstance at :48 and its comment)
- Java/DependencyInjectionTest.java (D04b)

Exact source evidence:
The instance registration is a separately named method, and its comment
explains the overload rule. The test fixture uses addSingletonInstance for
the TimeProvider. D04b registers a class with addSingleton and asserts that
an instance of that class is returned.

Reason:
The fix is present in the code and D04b now passes.
