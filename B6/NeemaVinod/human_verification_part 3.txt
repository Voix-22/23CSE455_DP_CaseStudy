4. Cross-Language Behaviour Verification

The reviewer should compare each implementation against the common specification and the original C# reference.

Strategy pattern

- [ ] Verify standard rental pricing.
- [ ] Verify weekend surcharge calculations.
- [ ] Verify seasonal pricing rules.
- [ ] Verify policy-selection precedence.
- [ ] Verify boundary cases, such as rental intervals crossing weekends or seasonal months.
- [ ] Check that all implementations use consistent inputs and expected outputs.
- [ ] Record any differences in behaviour.

Repository pattern

- [ ] Verify create operations.
- [ ] Verify retrieval of existing records.
- [ ] Verify behaviour when records do not exist.
- [ ] Verify update operations.
- [ ] Verify delete operations.
- [ ] Check invalid-input and error-handling behaviour.
- [ ] Determine whether storage behaviour is equivalent across languages.
- [ ] Record differences between in-memory storage and database-backed persistence.

Note: Similar method names do not establish equivalent behaviour. The reviewer must inspect the implementation and, where possible, verify the output using tests.
